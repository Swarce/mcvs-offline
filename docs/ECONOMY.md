# MCVS Offline economy

How every item of Modern Combat Versus 1.17.32 becomes obtainable offline, what it costs, and how to tune it.
Owner: CONTENT (`tools/content-gen`, `server/Content`, `server/Services/Crm`, `server/Services/Assets`).
Evidence: report 04 (economy), verify-C5 (unlock-all, store paths), verify-C4 (match rewards), the decoded
1.17.32 catalogue. Protocol details: [protocol/content.md](protocol/content.md).

## 1. Principles

* **VersusCoins is the shop currency.** It is the only repeatable currency: every PvP match pays it (the in-process
  GS fills the room with bots, verify-C4), with a per-division win/defeat/MVP amount and a daily cap. Hard currency
  (diamonds) is finite offline (≈1,425 from all league rank-ups, verify-C5), Credits only fill the loot-crate meter,
  `SoftCurrency`/`AgentsCurrency` are legacy (the game converts them).
* **The game's own logic grants everything.** The server only serves prices (CRM `offline_store`); purchases run in
  the in-process TS (`GameOfflineStore.BuyItemRequest`/`BuyMercRequest`/`BuyKillsignatureRequest`), which checks the
  balance, claims the reward and saves the profile. Nothing is granted by the server behind the game's back.
* **Use the screens the client actually has** (verify-C5 (d), `GM/GameOfflineStore.cs`, `GM/GameUnifiedStoreComponent.cs`):

  | Category | Where it is sold | Reward id | Notes |
  |---|---|---|---|
  | Mercs (21) | merc detail screen ("unlock" button) | `UnlockMerc_<id>` | any currency of the first billing method; we list VersusCoins and HardCurrency |
  | Skins (39) | skins shop | `MercSkin_<merc>_<skin>` | no `#IAP`/`#LOCKED` category, or the client hides/locks them |
  | Kill-signature avatars (1,512 released) and backgrounds (35) | signature screen | `KillSignature_Avatar/Background_<id>` | first price is charged |
  | Weapons (13 alternates) | VersusCoins hub tab | `MercWeapon_<merc>_<weapon>` | the dedicated weapon-store path is dead code |
  | Camos (4,409 merc×camo) | hub, per merc | `WeaponCamo_<merc>_Random` + 10-pack | resolves to a still-locked camo of that merc |
  | Accessories (5,208 merc×jersey) | hub, per merc | `MercAccessory_<merc>_Random` + 10-pack | resolves to a still-locked accessory |
  | Gear slots (109) | hub | `GearSlot_<merc>_<slot>` | |
  | Mods (all tiers incl. T4/perks) | hub, per merc | `ModTier_<merc>_4` | T1–T3 also come from MOD crates |
  | Signature sounds (4) | hub (and the signature screen's sound list) | `KillSignature_Sound_<id>` | |
  | Crates (19: loot, MOD, perk, ultimate, tokens, gear tiers, agent crates) | hub | `Crate_<id>` | opened server-side, repeatable |
  | VIP 30 days | hub | `SubscriptionCard_30` | daily VIP rewards incl. the VIP camo pool |

  The hub (`#VersusCoins` category) lists an entry only while its first reward is still available
  (`RewardPrototype.IsAvailable`): owned items, items of locked mercs and empty crates disappear on their own, so the
  list shrinks as the player progresses. Two exceptions stay visible: `ModTier_*` (no ownership check in the client)
  and `MercAccessory_*_Random` (the client's availability check does not look at the pool). Buying an exhausted
  mystery accessory pays out the game's duplicate compensation (`AlternateRewards`) instead.
* **The Cosmetic crate is the play path for the no-source set** (§5): ~600 cosmetics that nothing in 1.17.32 hands out
  (avatars, backgrounds, sounds 2–5, 16 skins, 12 hidden jerseys, the agents Witch and Bli-P) come from a random crate
  in the daily missions, the weekly event and the season rewards, together with the camos and jerseys the VIP pool
  used to give. The shop keeps selling what it sold.
* **Excluded on purpose:** the Kayac (Japan) collaboration camos/accessories and the 3 skins the 1.17.32 tables flag
  `Locked` (collab skins), ecomm-only ids that have no design-table row (the client has no specs for them), the
  placeholder merc 0, `Mod_*` items (hidden in generic tabs by an inverted `IsAvailable`), and anything `Reset*`.
  Real-money IAP is not offered: `iap` is `{"prices":[]}` (protocol/content.md).

## 2. Prices (pricing.json defaults)

Prices are generated by `tools/content-gen` from `tools/content-gen/pricing.json`, rounded to 5. Mercs and skins also
accept HardCurrency at 1 HC = 10 VC.

| Category | Rule | Items | Total VC |
|---|---|---:|---:|
| Mercs | by rarity: R1 800 · R2 1,500 · R3 2,500 · R4 3,500 · R5 5,000 · R6 7,000 | 21 | 76,400 |
| Skins | 2,000; crate-exclusive 3,500 | 39 | 84,000 |
| Weapons | 50 per weapon fragment the game would require, at least 2,500 | 13 | 44,000 |
| Avatars | by rarity: R1 50 · R2 100 · R3 200 · R4 400 | 1,512 | 117,100 |
| Backgrounds | 200 (purchasable in the tables), 400 (reward-only) | 35 | 9,400 |
| Signature sounds | 1,000 | 4 | 4,000 |
| Camos | 50 each, 10-pack 450 | 4,409 pairs | ≈198,000 (packs) |
| Accessories | 50 each, 10-pack 450 | 5,208 pairs | ≈234,000 (packs) |
| Gear slots | 800 | 109 | 87,200 |
| Mod tiers (all mods of a merc) | 12,000 | 21 | 252,000 |
| Crates | loot 600 · MOD T1/T2/T3 400/800/1,600 · random MOD 1,000 · perk/ultimate 2,500 · tokens 500 · gear T1–T5 300–3,000 · agent crates 2,000–8,000 | 19 | repeatable |
| VIP 30 days | 15,000 | 1 | repeatable |

`server/Content/economy.json` → `summary` has the exact generated counts and totals.

**Earn rates it is balanced against** (1.17.32 tables, verify-C4/C5): a PvP win pays 50–170 VC by division
(defeat ≈40%, MVP bonus extra) with a daily cap of 1,000–3,000 VC; agent mastery and league rank-ups add
≈26,500 VC once. With bot-filled matches of a few minutes the daily cap, not play time, is the limit:

* the "core" (every merc, weapon and skin, ≈204k VC) takes roughly 70–200 days at the cap depending on division,
  less with the mercs that loot crates (Credits) hand out anyway;
* everything (≈1.1M VC, two thirds of it cosmetics) is a long-term collection.

That is deliberately close to the original pace. Players who want it faster use the multipliers below (or the
unlock-all switches).

## 3. Tuning

### At runtime (settings.json, no rebuild)

| Setting | Effect |
|---|---|
| `economy.priceMultiplier` (1.0) | scales every generated price (integers, at least 1) |
| `economy.versusCoinsMultiplier` (1.0) | multiplies VersusCoins win/defeat/MVP amounts **and** the daily cap (`VersusCoinsMatchRewards` via `_OverrideTables`) |
| `economy.creditsMultiplier` (1.0) | same for Credits (`CreditsCurrencyMatchRewards`): faster loot crates |
| `economy.xpMultiplier` (1.0) | divides the XP needed per player level and per agent-mastery level (`PlayerLevelXP.XPRequired`, `AgentsMasteryXP.XPCost`) |
| `crm.dailyCapMultiplier` (1.0) | extra factor on the two daily caps only |
| `crm.offlineStore` (`generated`) | `merge` also keeps the shipped preconfiguration's other items; `preconfig` serves the shipped catalogue only |
| `crm.redeemCoupons` (true) | shows Settings › Account › Redeem code |
| `economy.collector.enabled` (true) | the Cosmetic crate (§5); `false` restores the original rewards |
| `economy.collector.itemsPerCrate` (5) | items in one Cosmetic crate, 1–10 (§5) |

Examples: *relaxed* = `versusCoinsMultiplier 2` + `priceMultiplier 0.5` (≈4× faster); *fast* =
`versusCoinsMultiplier 5`. Multipliers are sent as `_OverrideTables` MUL cells (`"*2"`) on the existing rows listed in
`economy.json` (CRM can only change existing rows). The GS computes match rewards, so the cells are mirrored into
`_ServerConfig.default._OverrideTables`. Changes apply to the next CRM fetch (new session or match).

### What each match mode pays

* **Battle › Classic multiplayer** (bots fill it at once with `instantBots`): the full PvP rewards above: trophies,
  division progress, Credits and VersusCoins by division (daily caps), the MVP bonus and agent XP.
* **Special Event** (the game's Arena mode, generated by live ops, [LIVEOPS.md](LIVEOPS.md) §8a): the same PvP path,
  with the event's reward multipliers on top of the economy multipliers (below).
* **Tournaments** are private matches: never filled with bots (the game server skips the bot fill for private rooms;
  no setting changes that) and, by the game's design, no trophies, division progress, Credits, VersusCoins, MVP bonus,
  agent XP, stats or leaderboard entry. Start buys the prize crate's ticket (320, 640 or 760 HardCurrency, or the free
  ticket without a prize); a win sends the crate to the inbox, a draw refunds the ticket, a loss keeps it. The
  crate-track win count and achievements still count, and probably the daily and weekly objectives. HardCurrency is
  scarce offline, so a paid ticket is a gamble with it.
* **The hidden Practice tile** (`crm.practiceTile`, off by default): with the default `bottile` patch the same match as
  Classic; without it, the game's free bot match: before PvP activation the FTUE bot rewards (the `BotMatchesInfo` row, MVP
  currency, merc XP and career trophies), after it only the `BotMatchesInfo` reward (stock 5 Credits per win).

### Content (rebuild or override)

* Edit `tools/content-gen/pricing.json`, run `python3 -I tools/content-gen/content_gen.py`, rebuild. The hub order is
  `hubOrder`; crates/VIP sold are listed explicitly.
* Or drop a modified `offline_store.json` / `coupons.json` / `crm_overlay.json` into `<data>/content/`
  (`POST /_mcvs/crm/reload` or restart). Bad store entries are dropped and logged rather than breaking the shop.
* Power users: `crm.overlay` (deep-merged into the CRM document last), `crm.pointcutActions` (e.g. a daily login
  gift: `{"id":"daily_gift","type":"give_object","frequency":1,"item":"HardCurrency","quantity":20,"pointcuts":[{"name":"launch","conditions":[]}],"limit":[{"max":1,"interval":86400}]}`
  (`frequency` defaults to 0 = never fires; limits are kept per `id` in the profile)),
  `assets.coupons` (own coupon codes). An own code whose name starts with `UNLOCK` goes through the inventory ledger
  like the built-in ones (its rewards must be unlock ids with quantity 1); any other code (`GIFT500`) becomes one
  inbox message and may hold at most 300 rewards: a bigger one is refused with a WARN line ("would freeze the game's
  inbox") and a warning in the page's code list. `"delivery": "ledger"` or `"inbox"` in a definition overrides the
  name rule.

### Unlock-all (opt-in)

| Way | How | Notes |
|---|---|---|
| Coupon | Settings › Account › Redeem code: `UNLOCKALL` | the code's keys go into the inventory ledger, exactly like `unlockAll` (`UnlockGranter.GrantKeys`): every merc first, alone in its own batch (`UnlockMerc_<id>` for each merc but the starting one, then `ModTier_<id>_4`: every mod; not `UnlockMerc_ALL_MAX`, which crashed the reward display), then weapons, gear slots, signatures, camos, accessories, skins (≈11k keys) in batches of `unlocks.batchSize` (400) with a set_profile alert and a rewards popup each. The game gets `[]`: it shows "redeem successful" and makes one empty, unclaimable inbox message (7-day expiry). Each code works once per profile; `UNLOCKALL2`, `UNLOCKALL3`… redeem again but only write keys the ledger lacks. Smaller codes: `UNLOCKMERCS`, `UNLOCKWEAPONS`, `UNLOCKGEARSLOTS`, `UNLOCKSIGNATURES`, `UNLOCKCAMOS`, `UNLOCKACCESSORIES`, `UNLOCKSKINS` (all but signatures unlock the mercs first). `assets.couponsEnabled=false` disables codes. |
| Dev cheat menu | `devMenu: true`, then tap top-left, top-right, bottom-left, bottom-right, top-left, bottom-right | exposes destructive cheats too (verify-C5 (a)); off by default |
| Inventory ledger | `unlockAll: true` | the storage `inventory` section diff (STORAGE module, verify-C5 (c)); grants exactly what UNLOCKALL grants |

### Paid and unreleased content (opt-in codes)

All generated by `tools/content-gen` (`Catalog._find_paid` / `_find_unreleased`) into `unlocks.json` groups that are
**not** in its `"order"`, so neither `UNLOCKALL` nor `unlockAll` nor the shop ever includes them by accident.

| Code | Grants (1.17.32 data) |
|---|---|
| `UNLOCKPAID` | every merc (20, without the mods, so no level-up flood), then every item whose **only** shipped source was real money: 2,684 camos and 2,940 jersey pairs (140 jerseys x 21 mercs) that nothing but the VIP subscription's random pool hands out (`SubscriptionCard_30_Days_Milestones`: `WeaponCamo_Random_Random`, `MercAccessory_Random_Random`). 5,644 rewards. |
| `UNLOCKPAIDCAMOS` / `UNLOCKPAIDACCESSORIES` | the same split in two (mercs first in both) |
| `UNLOCKUNRELEASED` | 6 kill-signature avatars that were never released: `KillSignature_Avatar_1513`-`1518` (two "Kayac2" emblems, four Bli-P agent emblems) |

How the sets are decided, and their caveats:

* **Paid** = every source in the data (`_catalog.json` unlock kinds and random pools, without cheat/duplicate/unreferenced
  tables) is real money: IAP bundles, the first-purchase top-up bonus, the VIP subscription. The IAP bundles' items (16
  agent packs, `MercSkin_14_2`) and the top-up rewards (`UnlockMerc_10`, `MercSkin_10_2`) all have a free source too
  (crates, store, events), so they are not in UNLOCKPAID; they are in UNLOCKALL. Everything in UNLOCKPAID is released
  content and is also in UNLOCKALL. The shipped CRM preconfiguration is an old template, so "only source" is relative
  to what 1.17.32 ships; the live store may have sold more.
* **Unreleased** = defined in the game's tables (so the client has the specs to claim and display it), no shipped
  source, **and** no id in the live ecomm catalogue (`Config/game_object.json`), so Gameloft's server could not grant or
  sell it either, **and** its asset is in the data pack (`names.json`). "No shipped source" alone would also catch
  content the live server sold: Witch (17) and Bli-P (21) have no source in 1.17.32 but were played (2019 gameplay
  videos), and so would 16 skins, 1,404 avatars, 18 backgrounds, 4 sounds and 152 jerseys; all of those have live ecomm
  ids, are treated as released and stay in UNLOCKALL.
* Excluded everywhere (listed in `unlocks.json` "excluded"): the placeholder agent `UnlockMerc_0`; 86 ecomm ids without
  a design-table row (37 skins, 49 camos: the client has no specs for them); the 3 `Locked` skins
  (`MercSkin_10_5`, `10_6`, `13_4`, released as migration compensation but hidden by the client); the Kayac (Japan)
  collaboration camos (210) and jerseys (672 merc pairs), hidden by the client for every non-Kayac profile. An
  unreleased candidate whose asset is missing would be listed there too (none in 1.17.32). Sounds are never treated
  as unreleased content we can check (an audio event, not a file).
* `KillSignature_Sound_2`-`5` share the starting sound's asset (`sfx_ui_crate_reveal`); they have live ecomm ids, so
  they count as released (sold in the hub, part of UNLOCKALL).
* Redeeming a code that unlocks mercs when you already own them (UNLOCKALL2, UNLOCKMERCS2, a split code after
  UNLOCKALL, UNLOCKPAID after UNLOCKALL) writes nothing: the ledger already holds those keys. Up to build 16 the codes
  were inbox messages and a repeat paid the game's duplicate compensation for each owned merc (40 random gear,
  `AlternateRewards` `UnlockMerc_<rarity>`); that compensation is gone with the inbox delivery. A merc owned through
  a crate or the store but not through the ledger still is a new ledger key, and the TS claims it as a duplicate.

## 4. Live ops income (docs/LIVEOPS.md)

Weekly division seasons, daily missions and weekly events add a second, play-driven income on top of the match rewards
(our tuning, `tools/content-gen/liveops_tuning.json`):

| Source | Per | VersusCoins | Other |
|---|---|---:|---|
| Daily missions (3 of 6) | day | 450–600 | 30–35 Credits, the *Daily mission loot crate* (`Crate_Contracts`: mercs, tokens, gear, Credits) for all 3; one Cosmetic crate with one of the missions (its card shows the crate) |
| Weekly event (4 objectives × 3 milestones) | week | 7,600 | 80 Credits, 600 upgrade tokens, 16 Cosmetic crates (1, 1 and 2 per objective's tiers); final: 20 HardCurrency + one cosmetic event crate (`Crate_Event_<n>`, 65 in rotation) |
| End-of-season reward (the game's `PVPDivisionRewards`) | week | – | ranks 1–3: HardCurrency, a gear crate and a season emblem; 4–30: a Cosmetic crate of 1–4 × `itemsPerCrate` items by tier (it replaces one gear piece); 31–60: 120 Credits; `liveops.seasonRewardMultiplier` scales it |

For a player at the daily match cap (7,000–21,000 VC a week by division) that is about +35–60 % VC, the first
renewable diamonds (20 a week, ≈1,000 a year) and a steady source of the event-crate cosmetics (camos and jerseys
that the store sells only as mystery packs). Weekly modifiers (Coin rush ×1.5 VC, Credit rush ×1.5 Credits, MVP
bounty ×3 MVP, Rival surge ×1.25 both, Trophy fever ×1.5 division trophies) multiply into the same `_OverrideTables`
cells as the `economy.*` multipliers (one MUL cell holding the product), so both settings compose.

**Special Events** (Battle › Special Event, [LIVEOPS.md](LIVEOPS.md) §8a) are public PvP matches with the normal rewards
and the event's own multipliers (`ArenaModeEvent` `EndMatchRewardMultipliers`, applied by the GS in
`RewardComponent.GenerateCurrency` and the MVP reward): wins pay ×1.25 Credits and VersusCoins (×1.5 in the five
Competitive modes, which are best of three), defeats and the MVP bonus ×1. They multiply the division's table amount
after the `economy.*` and weekly-modifier cells (so the three compose), and the daily caps still apply: a Special Event
reaches the cap sooner, it does not raise it. Tuning: `liveops_tuning.json` `arena.multipliers` and per-mode
`multipliers` (0.1–10).

## 5. The Cosmetic crate

Build 9 (design and numbers: [design/economy-collector.md](design/economy-collector.md)). In the game it is called
**CUSTOMIZATION CRATE** (`crm.CrateCustomization`, a name no other crate uses); it is the game's unused
`Crate_Event_Special`, filled through CRM `_OverrideTables` cells. No game code is patched for it, but it needs the
patcher's default `store` patch (without it the crate stays off).

**Where crates come from** (from `collector.since`, 2026-11-09, a Monday; before that nothing changes):

| Source | Crates |
|---|---|
| Daily missions: the day's first mission | 1 a day |
| Weekly event: tier 1 and tier 2 of each objective | 1 each (8 a week) |
| Weekly event: tier 3 of each objective | 2 each (8 a week) |
| Season end, ranks 4–30 | one crate of 1–4 × `itemsPerCrate` items (Starter/Bronze 1, Silver/Gold 2, Platinum/Diamond 3, Master 4; at most 40 items) instead of one gear piece |
| Season end, ranks 1–3 | no crate: a ★★★/★★/★ season emblem the player does not own yet, on top of the usual reward |

A milestone holds at most one crate (the game reveals only the last crate of a claim), so the daily "complete all"
bonus and the weekly final keep their own crates and get no Cosmetic crate. A claim with a crate shows only the crate's
items; the milestone's VersusCoins, Credits and tokens are credited without being shown.

**What is inside.** Each item is one draw from 39 rows: 1 = 70 VersusCoins (only once everything is owned), 2 = a random
avatar, 3 = a random background, 4–7 = a random background plus signature sound 2–5, 8–23 = the 16 skins, 24–35 = the
12 hidden jerseys (for a random unlocked agent), 36–37 = Witch and Bli-P, 38 = a random camo, 39 = a random jersey. The
weights are made per player from the saved profile: 75 % of the draws go to the no-source items while some are left,
the rest to camos and jerseys, and inside each part every missing item is equally likely, so owned items are not drawn
again. Never in the crate: Kayac (Japan) avatars and items, the 36 starred season emblems (kept for ranks 1–3),
unreleased content. An unlock-all profile gets 70 VersusCoins per item.

**Pace** (5 items per crate, 25 crates a week for a regular player, simulated): the ~600 no-source items in about 8
weeks (casual ~18 weeks), everything including the ~9,400 camo and jersey pairs in about 81 weeks (casual ~4 years;
the shop's 10-packs stay the faster way to the camos and jerseys). 10 items per crate halves these times.

**Switches.** On the page (Settings › Economy): "Cosmetic crate" (`economy.collector.enabled`) and "Items per Cosmetic
crate" (`economy.collector.itemsPerCrate`, 1–10, default 5); both apply after the next match, also to crates already
earned but not opened. Switching the crate asks first, because the running daily missions and weekly event restart. The presets do not touch them. More keys for testers (in `settings.json` only: `baseShare`,
`weights`, `seasonCrates`, `maxSeasonItems`, `seasonEmblems`, `unlockableWindow`, `levelUpAvatars`, `exhaustedReward`)
are listed in the design, §4.4.

* **Kill switch**: `"economy": {"collector": {"enabled": false}}` (or `"collector": false`; saving the item count on
  the page keeps it off). A value the server cannot read counts as **off**, and the page says so; so does a
  settings.json the server cannot parse at all (until it is fixed, or repaired on the page, which starts from the
  defaults: on). Off: the events go back to their old rewards (the running day and
  week, and an ended week still waiting for its claims, are replaced once, losing their progress), ranks 4–30 get
  their gear piece again, and a Cosmetic crate that is still claimable pays 70 VersusCoins.
* **The guard and its latch file.** From a day before `since`, and for good once the server has handed out an event
  with the crate, every CRM document gives the crate at least a 5-cell "guard" (one row of 70 VersusCoins), so a crate
  can never be empty: claiming an empty crate throws on the menu server. "Handed out" is remembered in
  `<data>/collector-guard.json` (`cratesServed`, `firstWindow`, `event`); an unreadable file counts as set. Deleting
  it while the game is closed resets a test setup.
* **What the server sees**: `GET /_mcvs/crm` (`collector`: phase Dormant / Guard / Active and why, `since`,
  `cratesServed`), `GET /_mcvs/collector?account=<id>` (what was read from the player's save and what is left per
  category), `GET /_mcvs/liveops` (`collector`), and the Status screen of the page (one line).

## 6. Open points (device test)

* The VersusCoins hub renders weapons, gear slots, mod tiers, crates, packs and VIP (verify-C5 marks the SWF side
  unverified); names of our packs show the raw `crm.<name>` key unless the SWF uses the content's names.
* A merc detail screen with two prices (VersusCoins and HC) shows both buttons (the shipped preconfiguration had
  two-price mercs, so the client supports it).
* The ≈11k-reward UNLOCKALL inbox message (UI and save size) — gone: every unlock code is delivered through the
  ledger (inbox-freeze report: the inbox rebuilt every reward of every unclaimed coupon message on open and every 10 s).
* Keys a profile claimed earlier through a coupon inbox message (builds up to 16) are not in the ledger, so a code
  redeemed now writes them and the TS claims them again; for camos and jerseys the game's duplicate handling is
  unverified [G] (test once on a profile that claimed UNLOCKCAMOS from the inbox).
* MUL cells on integer table columns (`"*1.5"` makes a double) are converted back by the typed table readers.
* The Cosmetic crate on the phone (STATUS.md, build 9, checks 14–28): reveals, screen times, the season crate.
